# MIPS Visualizer

MIPS アセンブリを 1 命令ずつ実行し、レジスタ・メモリ・PC の値がどう動くかを見るための学習用シミュレーター。
麗澤大学「計算機科学の基礎」（2026年度秋学期）のために作った。mipsy web（UNSW）と同じアセンブリがそのまま動く。

## できること（MVP）

- **① かんたん**：使っているレジスタを名前つきの箱で表示し、読んだ（青）・書いた（オレンジ）を色で示す。データは変数（配列・文字列）として、スタックは `$sp` の矢印つきで表示する。1 ステップ ＝ ソースの 1 行
- **② 命令の中身**：PC、機械語の欄（op・rs・rt・rd・shamt・funct／定数）、32 個のレジスタ、命令メモリ、データメモリ（1 バイトずつ・リトルエンディアン）。1 ステップ ＝ 本当の命令 1 つ（疑似命令の展開も見える）
- **③ ブロック図**：CPU の部品（PC・命令メモリ・解読・レジスタ・ALU・データ領域・スタック領域）のあいだを、値の札が配線にそって動く
- **④ C から機械語へ**：C のプログラムが「コンパイラ（① 字句解析 → ② 構文解析 → ③ コード生成）→ ④ アセンブラ（.o）→ ⑤ リンカ → ⑥ ローダ」を通って実行されるまでを、段階ごとに見る（下の「C のコンパイラ」）
- 実行した命令の説明（日本語）：分岐の判定、飛び先の計算（PC＋4＋定数×4）、番地の計算、`slt` の符号あり・なし、`jal` で `$ra` に入る番地 など
- 1 ステップ実行・**1 ステップ戻る**・連続実行（速さ 5 段階）・ブレークポイント・行ごとの実行回数
- syscall 1・4・5・8・10・11・12（入力はコンソール欄から）
- エラーは日本語で、原因の行を示す（命令名の打ち間違いには候補を出す）
- 授業のプログラム（`presets/`）をメニューから開ける。URL で指定もできる

## URL

| 例 | 意味 |
|---|---|
| `?preset=08-sample03` | 第08回 sample03 を開く |
| `?preset=06-stack&mode=2&step=5` | モード②で開き、5 ステップ進めておく |
| `#code=...` | 「🔗 リンク」ボタンで作る。プログラムを URL に入れる（サーバーには送らない） |

## C のコンパイラ（モード④）

授業用に作った、C の一部だけを扱うコンパイラ（`src/compiler/`）。最適化はせず、教科書（Patterson & Hennessy 2章）の例と同じ考え方で素直に訳す。

- 使えるもの：`int` の変数・配列（グローバル・ローカル・引数の `int v[]`）、`if`・`else`・`while`・`for`・`break`・`continue`・`return`、関数（引数は4つまで）、四則演算・`%`・比較・`&&`・`||`・`!`・ビット演算・シフト・`++`・`--`・`+=` など、`printf`（`%d`・`%c` だけ）・`putchar`、`#include`（読み飛ばす）
- 使えないもの：`char` などほかの型・ポインター・構造体・`switch`・`malloc` など（日本語のエラーで知らせる）
- レジスタの決め方：関数を呼ばない関数（リーフ）は引数を `$a` のまま・変数を `$t` に置き、何も退避しない。関数を呼ぶ関数は引数と変数を `$s` に置き、`$s` と `$ra` をスタックに退避する。式の途中は `$t`（呼ぶ前に使用中の `$t` を退避）
- `main` は最後に `syscall 10` で終わる。ファイルが複数あるときは、ほかのファイルの関数を `int add(int a, int b);` のように宣言して使う
- .o（機械語・記号表・再配置表）はファイルを1つずつアセンブルして作り、リンカは置き場所を決めて `jal`（26ビット）・`la`（上位・下位16ビット）の番地を埋める
- 動かすときは、全部のファイルをつないだアセンブリをモード①〜③に渡す。テスト（`tests/compiler.test.ts`）で、手元の `cc` で動かした出力と同じになること、番地を埋める命令のほかは .o と実行ファイルの機械語が同じことを確かめている。期待値は `sh scripts/make_c_golden.sh` で作り直す

| URL の例 | 意味 |
|---|---|
| `?cpreset=c05-link&mode=4&stage=obj` | C の例「別のファイルの関数を呼ぶ」を ④ アセンブラ の段で開く |
| `?mode=4&stage=asm#cfiles=...` | 「🔗 リンク」で作る。C のファイルを URL に入れる |

## mipsy との互換

- テキスト 0x00400000・データ 0x10010000・`$sp` 0x7FFFFEFC、`main` から実行、遅延分岐なし
- 疑似命令の展開（`li`・`la`・`lw ラベル`・`blt` など）は mipsy／SPIM と同じ形なので、番地と機械語も同じになる（第08回の資料の機械語で確かめた）
- 値を入れていないレジスタを読むと止まる（設定で切り替えられる）。`sw` で退避して `lw` で戻すのは許す
- `add`・`addi`・`sub` は符号ありのあふれで止まる
- 浮動小数点の命令には対応しない

## 開発

```bash
npm install
npm run dev      # http://localhost:5173
npm test         # アセンブラ・シミュレーターのテスト
npm run build    # dist/ に静的ファイル
```

- `src/core/`：アセンブラ・シミュレーター・説明文（画面から独立）
- `src/ui/`：エディター（CodeMirror 6）と表示
- `presets/`：授業のプログラム。**解答は入れない**（公開されるため）
- `tests/golden/`：突き合わせテストの期待値。教員用の `mips_sim.py`（授業のリポジトリにある）で `scripts/make_golden.py` を使って作る

外部と通信しない。ブラウザに保存するのは、編集中のプログラムと表示の設定だけ。

## 公開

`main` に push すると GitHub Actions がテストとビルドをして GitHub Pages に公開する（リポジトリの Settings → Pages で Source を「GitHub Actions」にする）。
